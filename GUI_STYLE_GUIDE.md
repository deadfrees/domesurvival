# DOMESURVIVAL — GUI Style Guide

Статус: предложение для согласования на одной эталонной машине, 2026-09-12. Массовые изменения GUI не выполнены. Фактические экраны и зависимости перечислены в `dev/visual_overhaul/ui_wearable_audit.md`.

## Визуальный язык

Интерфейс — обслуживаемая промышленная панель внутри купола: тёплый серый металл, графитовые углубления, ограниченные цветовые метки, ясные крупные показания. Износ размещается по краям корпуса и у крепежа; текст, слоты и значения остаются чистыми. Свет не имитируется размытием, bloom или прозрачными неоновыми градиентами. Пиксельный рисунок и стандартный Minecraft font остаются основой.

## Предлагаемая палитра

Эти значения — дизайн-токены следующего этапа, не новые константы игровой логики. Сопоставить окончательно с выбранной эталонной машиной и `VISUAL_STYLE_GUIDE.md` до распространения.

| Роль | Цвет | Правило |
|---|---|---|
| Тёмное углубление | `#202729` | Фон шкал и пазов |
| Корпус | `#424946` | Главная поверхность; без шумной заливки под текстом |
| Кромка | `#727A72` | 1 px освещённой грани |
| Светлый металл | `#A8ADA1` | Редкие акценты, винт/ободок |
| Основной текст | `#E5E4D4` | Полная читаемость на графите |
| Вторичный текст | `#B5BDB2` | Единицы, пояснения; не делать малоконтрастным |
| O₂ | `#63BAC5` | Кислородная шкала + `O₂`, не общий цвет всех входов |
| Энергия | `#C5A153` | FE + символ молнии/контакт |
| Жидкость | `#608FAF` | `mB` + капля; конкретная жидкость сохраняет её реальный tint |
| Тепло | `#C27A4E` | Горение/нагрев, когда такое состояние существует |
| Предупреждение | `#D2AC58` | Знак и текст причины |

Ресурс и направление имеют разные обозначения. Цвет сообщает тип ресурса; направленная стрелка, подпись `ВХОД`/`ВЫХОД` и перечёркивание `ВЫКЛ` сообщают режим. Текущее значение `SideMode` — источник правды. Не перекрашивать вход как кислород, если грань принимает энергию или воду.

## Сетка, панели и типографика

- Логический пиксель GUI — базовая единица. Контуры 1 px, фаска панели 1–2 px, внутренние отступы обычно 6–8 px. Использовать целочисленные координаты и кратные масштабы текстур.
- Одна большая функциональная панель, инвентарь и компактная зона состояния. Угловые винты допустимы, но не у каждого вложенного прямоугольника.
- Слот сохраняет vanilla предмет 16×16 и привычную рамку 18×18. Координаты и индексы берутся из существующего Menu. Не рисовать дополнительный слот, который выглядит интерактивным, но не существует.
- Стандартный Minecraft font в масштабе 1×. Длинные значения компактно форматировать, полное значение показывать в tooltip. Не уменьшать текст до нечётких 0.72×; для уже существующего overlay это задача будущей компоновки, не повод менять Menu.
- Заголовок одной строкой, единицы рядом с числом, вторичная инструкция максимум 1–2 строки. Подписи должны помещаться на русском и английском; использовать translation keys при будущей правке вместо literal там, где возможно без изменения данных.
- Не менять контракт FE/RF или mB: интерфейс обязан показывать ту же величину. Унификацию надписи единиц делать только после проверки используемого ресурса; не пересчитывать численные значения ради оформления.

## Шкалы и состояние

Запас энергии, кислорода и жидкости показывать как заполнение с началом/концом шкалы. Процент — вторичный признак; tooltip хранит точное значение и ёмкость. Заполнение 100% не означает ошибку; статус берётся из меню. Уровень compressedFeed нельзя выдавать за давление. Если физического давления в данных нет, использовать подпись «Буфер сжатого воздуха» и обычную шкалу количества.

Машина в ожидании сохраняет нейтральный корпус. Акцентная рамка не должна беспрерывно мигать. Работа отмечается одним движущимся элементом, только когда существующее состояние подтверждает обработку. Отсутствие ресурса получает неподвижный значок и конкретную причину, например «Нет фильтра» или «Выход заполнен». Статус `NO_ENERGY` не заменять универсальным «Ошибка».

Кнопки имеют различимые normal/hover/pressed/disabled/focus. Сохранить hitbox и callbacks, клавиатурную навигацию и narration. Вариант disabled должен различаться формой/контрастом, а не одной прозрачностью. Не добавлять новые действия, даже если декоративная кнопка удобна для композиции.

## Стороны машины

Сохранить действующую функцию `machineSideForVisualSide`, ориентацию front/back и запреты отдельных граней. Показать переднюю сторону отличимым символом и дать tooltip относительной стороны. Окраска режима и рисунок порта должны совпадать с предметом в мире, но не обещать недоступный capability. Перемещение боковой панели — только синхронно с её клиентской областью hover/click; изменение самих Menu/slot positions не входит в первый этап.

## Ограничения конкретного проекта

`EnergyStorageTransferRateOverlay` — отдельный слой поверх четырёх энергобуферов: фиксированная маска `#30363A` и координаты 3…173 / 60…82. При будущем изменении буфера обновлять одновременно отрисовку overlay; не удалять реальные показатели приёма/выдачи. `MetallurgyGui` уже общий для двух печей и подходит для узкого повторного использования. Остальные Screen имеют собственные drawing helpers; извлечение общей библиотеки GUI делать отдельным небольшим клиентским изменением после эталона.

`OxygenComplexScreen` 360×326 и `BioincubatorScreen` 300×310 требуют проверки в малом окне. Часть выдвижных панелей выступает вправо за `imageWidth`. Проверять и закрытую, и открытую конфигурацию. Не вводить глобальное масштабирование всех GUI ради одного экрана: это размоет шрифт и может разойтись с обработкой мыши.

Oxygen HUD сохраняет ряд 9×9 со шагом 8, правила скрытия и сдвиг под водой. Его источник — `ClientOxygenState`; декоративная пульсация не меняет запас и не должна закрывать vanilla health/air. Старый отдельный tank-source icon не возвращается автоматически: код содержит мотивированное решение предыдущего playtest.

JEI сохраняет 180×70, ingredient roles, fluid renderer и все recipe/catalyst ID. Цвет стрелки, подписи и пустого drawable можно унифицировать. JEI не должен показывать выдуманную обработку или расход.

FancyMenu, FTB Quests и Joseph имеют собственные точки интеграции. Квестовый фон остаётся через native FTB theme; не вмешиваться в progression. Joseph сохраняет component ID 6501–6506 и GBPort API. Общие фоновые изображения допустимы в меню, но они не определяют плотность пикселя игровых машин.

## Проверка следующего GUI-эталона

1. Снять OLD/NEW одного экрана при одинаковом разрешении и GUI Scale; отдельно открыть side panel.
2. Проверить все существующие состояния на реальных данных: пусто, работа, нет энергии/сырья, полный выход, неверный фильтр; не моделировать отсутствующие в коде состояния.
3. Сравнить slot positions, hover, shift-click, number keys, drag, tooltips, keyboard focus и действия кнопок с прежним экраном.
4. Проверить русский/английский текст, значения 0/максимум/∞, длинные названия жидкостей/предметов.
5. Проверить HUD с бронёй и Curios, под водой, при обычном GUI и JEI; затем Embeddium в фактической сборке.
6. Зафиксировать ограничения, которые не были проверены в игре. Статический анализ не заменяет эти проверки.
