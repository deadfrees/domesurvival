## Соединения и передача

Шесть Boolean-свойств блока включают рукава по направлениям north/east/south/west/up/down. Трубы разных уровней соединяются; отключение стороны любого из соседей разрывает соответствующее соединение. Порт машины определяется через `ForgeCapabilities.FLUID_HANDLER` на обращённой к трубе стороне. Существующий обход сети поддерживает `ServicePassThroughTraversal` для жидкостей.

Лимит — общий бюджет связной сети за тик, ограниченный самым медленным участком. Это не независимая пропускная способность каждого ответвления. Собственного бака в трубе нет. Сеть сначала симулирует операции у источников и приёмников, затем выполняет согласованный перенос. Совместимость жидкостей определяет IFluidHandler приёмника.

Режимы: AUTO разрешает забор и отдачу; INPUT разрешает забор из соседней машины; OUTPUT — отдачу соседней машине; DISABLED отключает сторону. NBT `SideModes` хранит ordinal режима отдельным байтом для каждого направления. Эти идентификаторы и код не менялись.

## Исходное отображение

Каждый уровень использовал core `[6,6,6]–[10,10,10]` и северный arm `[6,6,0]–[10,10,6]`, одну текстуру с растянутыми UV. Multipart всегда добавляет core и условно шесть повёрнутых arms. Исходные 15 JSON сохранены в `source_assets/baseline/fluid_pipes`.

Хитбокс шире старой модели: центр `[5.5,5.5,5.5]–[10.5,10.5,10.5]`, рукава шириной 5 до границ блока. Новые модели вписаны в этот неизменённый объём.

`FluidPipeBlockEntityRenderer` не рисует содержимое; новые модели также используют обычный Minecraft JSON multipart. Существующий cutout-слой совместим с полностью непрозрачными новыми PNG. Синяя капля — постоянная маркировка назначения трубы, а не индикатор воды, заполнения или активности.

## Инструменты и границы работ

Blender 5.2.1 LTS обнаружен в Microsoft Store package в `C:/Program Files/WindowsApps`. Store launcher в текущем сеансе не запускает Python. Копия установленного Blender в игнорируемом `dev/fluid_pipes/runtime_blender` успешно запускается через терминал; установка, Windows ACL и настройки не менялись. Геометрия, UV, материалы, .blend и экспорт создаются через Blender Python API.

Производственный объём изменения: 15 JSON и 18 PNG жидкостных труб. Java, рецепты, локализация, характеристики и другие ассеты этим конвейером не изменяются. После исходного снимка в рабочей папке отдельно восстановились 33 ресурса энергетических труб; их JSON структурно, а PNG побайтно соответствуют ранее одобренному коммиту `a1ce5be`. Это зафиксировано в `dev/fluid_pipes/external_energy_snapshot.json`; жидкостный конвейер сохраняет их текущие хеши и не включает в свои изменения.
