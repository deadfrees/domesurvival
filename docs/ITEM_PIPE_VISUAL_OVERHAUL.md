# DOMESURVIVAL — транспортные трубы

## Область изменения

Три существующих тира: `copper_item_pipe`, `steel_item_pipe`, `desh_item_pipe`, и `filtering_item_pipe`. Работа ведётся в существующей ветке `feature/infrastructure-phase-b`. Энергетические и жидкостные трубы не изменяются.

Оформление продолжает утверждённую серию материалов: сатинированный металл, узкие светлые фаски, ровные швы, небольшие крепления и сдержанная цветовая маркировка. Использованы выводы из [предыдущего анализа материалов модов](PIPE_MATERIALS_V2_REFERENCE_ANALYSIS.md); сторонние текстуры не включаются в поставку.

## Результаты аудита

- У всех четырёх блоков уже есть шесть независимых направлений соединения и `noOcclusion`.
- Основной корпус занимает `[6.25, 6.25, 6.25] — [9.75, 9.75, 9.75]`; плечо имеет ширину 3 единицы Minecraft.
- До изменения сервер показывал передачу двухтиковыми условными частицами. Эти частицы не содержали тип передаваемого предмета.
- Реальная доставка предметов происходит сразу в серверной логике. Анимация показывает завершённую передачу и не является дополнительным инвентарём.
- Рендерер блок-сущности ранее отображал только муфты подключения к инвентарям.
- У фильтра в мире были узкие цветные таблички вместо полноразмерных панелей, присутствовавших в его модели инвентаря. После замечания пользователя шесть панелей корпуса фильтра приведены к той же замкнутой раме, что у остальных тиров.

## Материалы и модели

Медь получает тёплые вставки, сталь — холодные светлые, desh — приглушённые сине-фиолетовые, фильтр — зелёные. Цвета направлений фильтра соответствуют `FilterRoute`: север — синий, юг — красный, запад — зелёный, восток — жёлтый, верх — белый, низ — фиолетовый. Они размещены на непрозрачном ободке.

Металл и стекло разделены через штатный `forge:composite`: `minecraft:cutout` для рамы и `minecraft:translucent` для стекла. Альфа стекла составляет 13–28%, основная поверхность — 16%. Металл имеет только альфа 0 или 1. Отдельные маски не накладывают непрозрачную плоскость поверх смотрового окна.

Габариты и соединения трёх тиров сохранены. У фильтра заменены только размеры шести наружных панелей на размеры панелей стальной трубы, как запросил пользователь. Блок-сущности, коллизии, маршрутизация, предметы, рецепты и таблицы добычи сохраняются. `uvlock=false` позволяет направленным островкам атласа поворачиваться вместе с плечом трубы.

Настраиваемые чёрные муфты у сундуков и машин также получили материалы соответствующего тира: четыре рамки из сатинированного металла и по три панели режима. Исходная геометрия муфт и зоны взаимодействия сохранены. Панель режима вынесена изнутри непрозрачной муфты на её сторону, обращённую к трубе, чтобы индикация была видна. Синий означает `INPUT`, оранжевый — `OUTPUT`, стальной серый — `DISABLED`. Новые текстуры имеют размер 128×128; режимы, меню настройки и механика портов не изменены.

Автоматизация: `source_assets/blender/scripts/create_item_pipe_family.py`, Blender 5.2.1 LTS, Python API `bpy`. Генератор использует неизменяемые исходные JSON из `dev/item_pipe_visual/baseline`, создаёт три варианта атласа для каждого вида, четыре упакованных `.blend`, четыре `.bbmodel` и общий обзор. Материал создаётся в корректном цветовом пространстве sRGB.

Отдельный редактируемый обзор двенадцати вариантов муфт создаёт `source_assets/blender/scripts/create_item_connector_preview.py`: `source_assets/blender/item_pipes/02_configurable_connectors.blend` и соответствующий PNG в `previews`.

## Отображение предметов

После успешного переноса сервер отправляет наблюдателям в пределах 64 блоков от маршрута один косметический пакет с копией `ItemStack`, его количеством, NBT и точками пути. Вместо повторной рассылки частиц каждый тик клиент интерполирует движение с прежним темпом: восемь тиков на сегмент.

Клиент хранит максимум 64 анимации. Очередь очищается при смене мира; чужое измерение игнорируется. Путь ограничен 4098 точками, нечисловые координаты отклоняются. Сеть передачи не загружает дополнительные чанки. Предмет отображается штатным `ItemRenderer` внутри текущей трубы, до слоя прозрачного стекла. При удалении трубы её рендерер больше не рисует предмет в этом блоке.

Позиции предметов вычисляются один раз за кадр и распределяются по блокам. Пустая труба не перебирает всю очередь анимаций.

Предметы не создаются как `ItemEntity`, их нельзя подобрать или продублировать анимацией. Инвентарная логика передачи не менялась.

## Сохранённые правила передачи

| Тир | Предметов за цикл | Пауза |
|---|---:|---:|
| Медь | 4 | 40 тиков |
| Сталь | 16 | 20 тиков |
| Desh | 32 | 10 тиков |
| Фильтр | По слабейшему обычному тиру сети | По слабейшему обычному тиру сети |

Сеть, состоящая только из фильтрующих труб, как и раньше, использует медный режим. Неуказанные в фильтре предметы проходят; совпавшее правило `NONE` блокирует предмет. Цветной порт `OUTPUT` забирает из объекта в сеть, `INPUT` отдаёт из сети объекту. Это существующее соглашение сборки.

## Проверка и воспроизведение

1. Blender: `--background --factory-startup --python-exit-code 1 --python source_assets/blender/scripts/create_item_pipe_family.py`.
2. Проверка материалов тем же Blender: `--python dev/item_pipe_visual/validate_assets.py`.
3. Изолированный клиент: `powershell -NoProfile -ExecutionPolicy Bypass -File dev/item_pipe_visual/run_review.ps1`.
4. Финальная сборка: `gradlew.bat -PdomeFullDev=true build --offline --console=plain` с Java 17.
5. Проверка JAR: `dev/item_pipe_visual/verify_release.py`.

Стенд создаёт новый плоский мир в `run/item-pipe-review`, временно перемещает 85 пользовательских модов из `run/mods` и возвращает их в `finally`, как штатный FULL DEV запуск. Рабочие миры не используются. Пробный Java-класс подключается только init-скриптом и не входит в релиз.

Итоги проверок сохраняются в `dev/item_pipe_visual/asset_validation.json`, `runtime/checks.txt` и `release_validation.json`. Игровые снимки находятся в `dev/item_pipe_visual/runtime`; обзор Blender — `source_assets/blender/item_pipes/previews/01_item_pipe_family.png`.

Финальная проверка 14 сентября 2026: 1740 проверок ассетов, 57 игровых проверок, все 256 сочетаний соединений четырёх блоков — PASS. Проверены фактические скорости трёх тиров, сохранение количества предметов, фильтрация, NBT, отключение порта, передача настоящего ItemStack на клиент и предел очереди. Обычная сборка `build` с тестами завершилась успешно; тестовый стенд исключён из JAR, 85 производственных модов возвращены на место.
