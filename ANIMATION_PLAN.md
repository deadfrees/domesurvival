# DOMESURVIVAL — план анимаций

Дата: 2026-09-12. Статус: аудит и план; новые анимации этим документом не включены. В первом проходе изменяется только согласованный визуальный эталон. Механика, Menu, NBT, capabilities, сеть и соединения сохраняются.

В исходниках не найдено системы GeckoLib или единого animation-controller для машин. JSON-модели сами по себе не дают вращения поршня. На данном этапе не добавлять новую библиотеку ради одного эффекта. Наличие `partialTick` в сигнатуре BER не означает, что renderer уже анимирован.

## Источник правды и границы

Мировой renderer может надёжно использовать синхронизированное blockstate `LIT`/`ACTIVE` и уже доставленные visual-поля block entity. Значения, передаваемые только открытым Menu через `ContainerData`, доступны GUI и не становятся автоматически доступны BER у закрытой машины. `saveAdditional` означает сохранение NBT и сам по себе не доказывает доставку состояния всем клиентам. До анимации по BE-полю проверить `getUpdateTag`, пакет и фактическое получение клиентом.

Не добавлять клиентские запросы capabilities/поиск сети каждый кадр. Клиентское движение не вызывает расход ресурса, рецепт, изменение side config или inventory. Не менять ticks обработки ради длины анимационного цикла. Декоративный цикл может зависеть от game time, но его видимость должна зависеть от реального состояния.

Предложенные `OFF`, `STARTING`, `RUNNING`, `STOPPING`, `ERROR`, `NO_POWER`, `FULL`, `BLOCKED` — **словарь представления**, а не новый enum сервера. `STARTING`/`STOPPING` допустимы только как короткое клиентское сглаживание перехода существующего active-флага; это не новый этап производства. `OFF` нельзя считать ручным выключением, если такого действия нет. `ERROR`/`BLOCKED` нельзя выводить из одного отсутствия progress.

## Производительность и реализация

Статический корпус остаётся baked-моделью. BER нужен лишь для действительно движущихся частей; текстуры, модели и draw helpers переиспользуются. Кэш должен учитывать resource reload, иначе F3+T оставит старую геометрию/текстуру. Не размножать уникальные RenderType на каждый кадр, не читать файлы и не создавать сложные модели внутри render.

Использовать tick + partialTick для плавной позы; ограниченный фазовый offset из позиции убирает одинаковое движение ряда машин без обращения к случайности каждый кадр. Небольшое сглаживание допускается в клиентском renderer; оно не откладывает серверное отключение или расход. На загрузке chunk сразу инициализировать позу по реальному состоянию, не проигрывать выдуманный запуск.

Держать движение внутри существующей видимой границы, либо явно учитывать render bounding box без изменения collision/selection shape. Для мультиблоков сохранить правило одного master-renderer. Сохранять lighting/overlay, сбалансированные pushPose/popPose, корректные normals и separation от непрозрачного корпуса. Для прозрачного бака обязательно проверить сортировку в мире.

Плановый предел нового эффекта на одной машине: 1–3 движущихся простых части, никаких многослойных светящихся оболочек. Это бюджет дизайна, не измеренный результат. Число частиц ограничивать существующей настройкой Minecraft, расстоянием и частотой, не спавнить на каждом render-frame. Профилировать несколько десятков видимых работающих машин и сравнивать одинаковый save/camera/settings с исходным вариантом; проценты FPS до измерений не обещать.

## Приёмка

Проверять active/inactive, переход после потери питания, полный выход, выгрузку/загрузку chunk, pause, выход и вход в мир. Для точных GUI-значений открыть второй клиент и подтвердить совпадение состояний. Для wearable: standing/walking/running/crouching/swimming/jumping, первый и третий вид, обычные и slim руки, маска вместе со шлемом и баллоном. Проверить F3+T и отключённые частицы. Сравнить без Embeddium и с установленным в сборке Embeddium при одинаковых настройках.

Build и статическая проверка подтверждают только компиляцию и целостность ресурсов. Визуальная корректность, FPS, clipping и отсутствие ошибок OpenGL считаются проверенными только после фактического запуска Minecraft; невыполненные пункты явно остаются открытыми.
