# Восстановление DomeSurvival после переустановки Windows

Эта папка хранится на F:. Не удаляйте и не форматируйте раздел с этой копией
во время установки Windows. Буквы дисков в установщике могут отличаться:
сверяйте раздел по объёму и содержимому. Сохраните копию на отдельном носителе,
если планируете удалять разделы всего физического диска.

## Что сохранено

- `project`: весь проект, включая `.git`, исходники, модели Blender/Blockbench,
  миры `run/saves`, моды, конфигурацию, локальные исходные материалы, сборки
  и файлы, которые Git игнорирует.
- `DomeSurvival-all-branches.bundle`: независимая копия всех Git-веток и тегов.
  Дополнительные LFS-объекты, если они есть, находятся в `project/.git/lfs`.
- `toolchain/jdk-17.0.12`: JDK 17, использовавшийся для сборки.
- `toolchain/gradle-home`: Gradle Wrapper и локальные зависимости из профиля пользователя.
- `codex-home`: история, настройки, навыки, плагины и вложения Codex.
  SQLite сохранён через согласованные снимки и проверен `quick_check`.
- `manifest.json`: SHA-256 каждого сохранённого файла и список исключений.
- `verification.json`: результат копирования и проверки, номер коммита.

Пароли входа Codex (`auth.json`), его песочница, браузерные сессии и временные
каталоги не переносятся. После установки войдите в аккаунт заново.
Локальные данные Codex хранятся в CODEX_HOME (обычно `.codex`):
https://learn.chatgpt.com/docs/config-file/config-advanced#config-and-state-locations
Копия истории отражает момент создания снимка; текущий диалог может продолжаться.

## Как продолжить работу

1. Установите Git for Windows и Codex. Сначала выполните восстановление истории,
   затем запускайте Codex. JDK для проекта уже сохранён рядом.
2. Откройте `project` в Codex. Можно работать прямо на F:.
3. `BUILD.cmd` запускает `test build --offline`, используя сохранённые JDK и Gradle.
4. `RUN.cmd` запускает существующий FULL DEV профиль с CustomNPCs.
   Первый запуск после переустановки может пересоздавать пути/кэш и требовать Интернет.
5. Сначала проверяйте проект через эти запускаторы: они не зависят от старого
   имени пользователя, буквы диска или пути установки Java.

Старые вспомогательные сценарии/история могут содержать `C:\domesurvival`.
После переустановки можно выполнить из PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\LINK-OLD-PATH.ps1
```

Это создаст ссылку `C:\domesurvival` на `project` рядом с этим файлом.
Существующую папку на C: сценарий никогда не заменяет. Пока оригинал существует,
ничего делать с этой ссылкой не нужно. Старые сценарии с жёстким путём Java
лучше запускать через `BUILD.cmd`, либо установить JDK в прежнее место.

## Восстановление Codex

Закройте Codex. Выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\RESTORE-CODEX.ps1
```

Если новая `.codex` уже существует, сценарий остановится: сначала переименуйте
её, например в `.codex-new-before-restore`. Снимок копируется в профиль текущего
пользователя; пути профиля в настройках и индексах БД обновляются автоматически.
Исторический текст переписки не переписывается. Для старого пути проекта используйте
`LINK-OLD-PATH.ps1`. Восстановление истории в новой версии приложения не проверено:
при проблеме сохраните эту резервную копию и покажите ошибку Codex.

## Проверка и резервный Git-вариант

`VERIFY.cmd` заново проверяет все файлы по SHA-256. Запускайте до начала работы:
после редактирования или сборки изменённые файлы закономерно отличаются от снимка.
Git можно восстановить отдельно в новую пустую папку:

```powershell
git clone .\DomeSurvival-all-branches.bundle DomeSurvival-git-only
```

Такая Git-копия не включает миры, сторонние моды и игнорируемые локальные файлы;
полная рабочая копия находится в `project`.
